# 数据扩容与公开岗位库说明

## 1. 为什么当前 20 条 jobs.json 不够

内置 `data/jobs.json` 仅包含 20 条手写样例岗位，覆盖方向有限（主要是大模型应用算法、推荐算法、部分 NLP/CV）。
在 Demo 演示层面可以跑通，但作为"算法系统"项目缺乏说服力：

- 岗位多样性不足（缺少海外 AI 公司、真实 JD 样式）
- 无法验证数据接入管线的可扩展性
- 对外演示时显得像"玩具样例"

## 2. 为什么不直接爬 Boss/智联/牛客

- **合规风险**：大部分招聘平台的 ToS 禁止爬虫；爬取后的数据分发也有法律风险
- **反爬成本高**：平台有滑块验证、IP 限制、动态渲染等反爬手段
- **数据质量差**：爬回来的 HTML 需要大量清洗，格式不统一

因此本项目的策略是：**优先使用公开数据集 + 公开 ATS API**，不碰需要登录/反爬的平台。

## 3. 为什么先用公开数据集 / ATS 公共数据

### 公开数据集（离线可用）

| 数据集 | 大小 | License | 特点 |
|--------|------|---------|------|
| `arjun10g/na-tech-jobs` | 12.3k | MIT | 北美技术岗，字段干净（role_family/seniority/tech_stack） |
| `Aramente/eu-tech-jobs` | 894k | CC-BY-4.0 | 欧洲技术岗，有 title/location/seniority/stack/description_md |
| `edwarddgao/open-apply-jobs` | 10.2M | MIT | 全球岗位，来源 Greenhouse/Lever/Ashby |

### 公共 ATS API（近期目标）

- Greenhouse Job Board API：`https://boards-api.greenhouse.io/v1/boards/{company}/jobs`
- Lever Postings API：`https://api.lever.co/v0/postings/{company}`
- Ashby Job Postings API：`https://api.ashbyhq.com/public/posting-api/v1/jobs`

## 4. 统一岗位 Schema

每条岗位在项目中遵循以下字段（与内置 `jobs.json` 兼容）：

```json
{
  "id": "md5_hash_12chars",
  "title": "岗位名称",
  "company": "公司",
  "city": "城市",
  "stage": "实习/校招/社招/不限",
  "direction": "岗位方向",
  "skills": ["技能列表"],
  "project_signals": ["项目信号"],
  "jd": "岗位描述全文",
  "interview_themes": ["面试主题"],
  "source": "数据来源",
  "source_url": "原始链接",
  "posted_at": "发布时间",
  "data_quality_score": 85
}
```

## 5. 数据清洗流程

```
外部原始数据 (JSON/CSV/API)
        |
        v
normalize_public_job()  ← 字段映射 + 标准化
        |
        v
infer_direction()       ← 从 title/description 推断方向
infer_stage()           ← 推断阶段
_find_skills()          ← 正则提取技能关键词
_find_project_signals() ← 提取项目信号
        |
        v
_quality_score()        ← 质量评分 (0-100)
        |
        v
deduplicate_jobs()      ← title+company+city 去重
        |
        v
merge_jobs()            ← 与内置岗位合并
        |
        v
data/public_jobs_sample.json  /  data/jobs_merged.json
```
