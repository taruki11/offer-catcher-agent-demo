# 模型路线说明

## 当前：API 增强（非蒸馏）

LLM API 作为**可选增强层**，负责 JD 解析、简历解析和匹配分析的非结构化文本理解。排序和决策仍由可解释公式完成。未配置 API Key 时，规则版所有 Agent 仍可完整运行。

**为什么选 API 增强而非微调：**
- 没有真实"简历→JD→初筛结果"标注数据
- 没有 HR 评价偏好数据
- 样本量不足（30-80 条岗位）
- API 增强可快速验证算法框架，微调需要数据闭环

## 未来：蒸馏路线

当积累足够真实投递反馈数据后：

1. **数据收集**：简历文本 + JD 文本 + 投递结果（通过/初筛/面试/Offer）+ HR 评价
2. **标签生成**：用强 LLM（如 DeepSeek-V3/GPT-4）作为 teacher，对简历-JD 对生成 PassScore、Action、关键词覆盖率标签
3. **小模型训练**：
   - PassScore 预测：XGBoost / LightGBM 或 Qwen2.5-7B 微调
   - Action 分类：多分类小模型
   - 简历改写质量评估：RLHF（基于 HR 偏好反馈）
4. **部署**：小模型本地推理，无需 API 调用，延迟 < 100ms

## 本项目和"直接问豆包/DeepSeek"的区别

| 维度 | Offer 捕手 | 直接问 LLM |
|------|-----------|-----------|
| 岗位排序 | 批量 8-30 个岗位一键排序 | 逐条问，无法批量对比 |
| 决策可解释性 | 可解释公式（Match/Pass/Risk/Growth） | 黑盒回答，无法追问权重来源 |
| Agent 状态 | 7 个 Agent 有结构化输入输出契约 | 无状态，每次从零开始 |
| 证据链 | 每个缺口/改写对应具体 JD 要求 | 可能幻觉 |
| Eval | Match/Priority/Action 三维评估 + Error Taxonomy | 无系统评估 |

**总结**：本项目不是"调 LLM API 聊天"，而是用 LLM 做非结构化文本理解，将排序、策略、评估交给可解释公式和结构化 Agent 管线。未来蒸馏也基于这套管线产出的结构化数据。
