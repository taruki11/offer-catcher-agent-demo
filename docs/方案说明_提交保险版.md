# Offer 捕手：基于多 Agent 协作的大模型应用算法系统

## 问题诊断

学生求职需一个**结构化决策系统**回答：哪个岗位最匹配？简历差在哪？该先投哪个？这不是单次问答能解决的，需多 Agent 协作完成"画像→召回→排序→诊断→改写→规划"闭环。算法挑战：简历/JD 是非结构化文本、排序必须可解释、缺乏标注数据不能微调。

## 方案设计

7 个 Agent 协作：Profile Builder（解析简历）→ JD Intelligence → Opportunity Scout（关键词召回）→ Application Ranker（可解释公式排序）→ Gap Diagnosis → Resume Conversion → Strategy Planner。

核心设计：LLM 负责"理解与生成"，排序交给可解释公式：`ApplyPriority=0.40×Match+0.30×Pass-0.15×Risk+0.15×Growth`。LLM 是可选增强层，无 API 时规则版仍完整运行。

## AI 选型

不做微调——无真实标注数据、无 HR 偏好、样本不足，硬做微调是伪实验。当前 LLM structured output+规则公式验证；后续有投递反馈后训练 PassScore 预测模型。

## Eval 与迭代

**多 Agent 不能只端到端评测**——需拆为 Match/Priority/Action 三维。

当前指标（8 Golden Cases）：Match Top1 **100%**、Priority Top1 **85.7%**、Action **75%**、Recall@5 **100%**。

四轮 Eval 驱动迭代：初始 Match=42.9%+E7 误报×8→修复 E7→Strategy 校准（Action 25%→75%）→Matcher 方向权重调优（Match 71.4%→100%）。剩余失败 case 均为合理边界（方向迁移、外部上下文差异），非系统崩溃。
