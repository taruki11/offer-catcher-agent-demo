# 演示脚本（3 分钟）

## 开场（30 秒）

"Offer 捕手是一个**基于多 Agent 协作的大模型应用算法系统**。它把求职决策建模为 7 个 Agent 的结构化协作流程。和普通 ChatGPT 套壳不同，这不是一个问答机器人——每个 Agent 有清晰的输入输出契约，LLM 只负责理解和生成环节，排序决策交给可解释公式。"

## 主流程演示（60 秒）

"（粘贴示例简历，点击运行）可以看到 7 个 Agent 依次执行：Profile Builder 解析出技能树和项目信号，Application Ranker 用加权公式计算 Match/Pass/Risk/Growth 四个维度，最终输出 ApplyPriority 排序。这个公式是可解释的——每个权重都有业务含义，面试时能讲清来源。"

"（展示岗位榜单）左侧是投递优先级榜单，每个岗位都能展开看匹配维度、能力缺口和简历改写建议。右侧是策略面板：Top3 推荐 + 7 天投递计划 + 面试准备计划 + 报告一键导出。"

## Eval 诊断（60 秒）

"（展开底部 Eval 诊断区域）**这不是一个跑完就完的 Demo——我们搭建了完整的 Eval 和 Error Analysis 框架。** 用 8 Core + 7 Stress golden cases 评估系统表现："

"**Core Eval: 8/8 通过（100%）**——Match Top1 100%、Priority Top1 85.7%、Action 87.5%、Recall@5 100%。**Stress Eval: 7/7 通过（100%）**——边界情况也全部通过。"

"（展开 Corpus Eval 报告）我们还做了 Corpus-level Eval：在 500 条岗位库上对 7 个代表性 Query 评估检索质量，Top1 方向命中 >= 71%，空字段数为 0。"

## 数据透明度（30 秒）

"（展开侧边栏"岗位库数据透明度"）很多 Demo 不敢展示数据来源，我们明确标注：当前岗位库 500 条，其中 452 条来自 Hugging Face 公开数据集，48 条是 curated seed 覆盖库。不冒充真实爬取，数据边界清晰。"

## 算法深度亮点（30 秒）

"多 Agent 系统不能只做端到端评测。我们拆成 Match 榜、Priority 榜、Action 三个维度，每个 Agent 的错误都能追溯。经历了四轮 Eval 驱动的迭代：修复 E7 误报、校准 Strategy 动作阈值、调优 Matcher 方向权重到 Match Top1 达到 100%。这是**可评估、可诊断、可迭代**的算法系统，不是一次性调参跑通的 Demo。"
